# 总结并新开：Codex 自主模式

> 状态：已收缩为最小控制面。

## 当前行为

小新不再生成摘要、规定摘要结构、校验摘要、注入历史、创建或命名目标任务，也不拦截用户刚提交的新请求。

用户在空闲任务上点击“让 Codex 总结并新开”后，小新只向该任务发送一条普通用户消息：

```text
总结必要上下文，开启新的会话任务
```

Codex 自己决定需要总结哪些内容，以及如何创建、命名和继续新任务。小新只复用既有的安全重放通道，把这条消息送达当前顶层、可见且空闲的任务；原任务不会被自动归档或删除。

## 边界

- 正在运行的任务不会被小新中断；等待任务空闲后再操作。
- 不再按累计 Token、缓存命中、轮数、上下文比例或压缩次数自动阻断用户请求。
- 不保存用户提示词、摘要正文或新任务内容；重放消息仅在本机 0600 通道与进程内短暂存在。
- 小新只确认“指令已发出并由 Codex 接收”的发送层结果；新任务是否真的创建、是否可打开、总结质量是否充分，属于 Codex 的实际运行结果，需要人工确认。

## 为什么采用此模式

真实测试表明，Codex 已经具备在当前任务中总结必要上下文并自主开启新任务的能力。Guardian 再承担第二套摘要与任务创建协议只会增加 Token、状态机、失败分支和错误归因，并不能提高这条主路径的可靠性。

因此，是否新开仍是用户的明确操作；怎样总结、怎样创建由拥有完整会话语义的 Codex 负责。

## 验收

在一个可丢弃的空闲任务中点击入口，确认当前任务收到上述固定指令，并观察 Codex 是否创建了可打开的新任务。若 Codex 的行为变化，优先修正这条普通指令，而不是恢复 Guardian 的摘要或建任务控制面。
