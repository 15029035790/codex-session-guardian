# 小新会话管家产品宪章

> 状态：v1 冻结
>
> 冻结日期：2026-08-12
>
> 作用：这是产品定位、范围和验收的最高约束。功能、界面和技术方案与本文件冲突时，必须先修正方案；不得用既有实现反向改变定位。

## 1. 核心定位

小新会话管家是 **Codex 的本地智能执行控制与守护层**。

用户只需将默认配置保持为 `sol / medium` 并发送任务。小新负责：

1. 为当前任务匹配足以高质量完成、同时 Token 成本更合理的模型与推理深度；
2. 持续监控执行中的偏航、错误和不必要消耗，并及时提醒或在授权边界内纠正；
3. 跨项目、跨任务、跨版本观察 Codex、Skills、Agents、Hooks、全局与项目级 `AGENTS.md` 等工作流配置，发现用户难以直接感知的系统性问题。

对用户的统一承诺是：

> 你只管发送任务，小新负责让 Codex 用合适的配置、沿正确的路线把任务完成。

小新不预测用户的下一个任务。它只针对已经到来的当前任务做决策，并用后续执行与验证证据持续校准。

## 2. 优化目标

小新不追求绝对 Token 最少，也不追求始终使用最强模型。它优化的是：

```text
在满足任务质量与风险门槛的前提下，最小化每个已验证有效结果的总 Token 与返工成本。
```

任何降档都必须保留质量门槛；任何升档都必须有任务复杂度、风险或执行证据。环境失败、权限失败、单次工具错误和等待用户操作不能单独成为升档依据。

## 3. 三个核心闭环

### 3.1 任务配置匹配

输入是当前任务契约、风险、范围、可验证性、工作流环境和个人历史；输出必须是针对该任务的配置决策，而不是静态任务类型或使用习惯。

每次决策至少包含：

- 当前配置与建议配置；
- 决策原因和置信度；
- 使用的事实、规则或可比样本；
- 升级、回退和停止条件；
- 最终质量、Token、耗时与返工证据；
- 该结果能否进入后续个性化路由证据。

默认入口固定为 `sol / medium`。高配置可在证据充分时降档；低配置或执行能力不足时可以升档。配置是否真正自动生效，必须由技术探针证明，不能由界面文案代替。

### 3.2 执行过程守护

小新应优先发现用户无法持续观察的执行异常，包括但不限于：

- 子 Agent 不必要地继承完整上下文；
- Agent 并发失控、职责重叠或重复解决同一问题；
- 重复读取、无变化重试、工具输出膨胀和无证据空转；
- 错误、危险或明显偏离目标的工具调用；
- 上下文污染、约束遗忘、计划反转和任务范围漂移；
- 把计划、局部成功或代码存在误判成已完成；
- 任务长时间没有产生新的完成证据。

能力按三个等级演进：观察、提醒、控制。前期以准确、及时、可行动的提醒为目标；只有高置信、低风险、可逆且已获授权的处置才能自动执行。

### 3.3 工作流健康

小新把 Codex 版本、模型版本、Skills、Agents、Hooks、MCP、工具暴露、权限、全局和项目级 `AGENTS.md` 视为任务执行环境的一部分。

工作流健康闭环必须能够：

1. 建立配置清单、作用域和版本指纹；
2. 感知变化并记录生效边界；
3. 关联变化前后的触发、Token、质量、失败和返工；
4. 从跨项目重复现象中发现疑似回归；
5. 区分相关性、受控证据和已验证因果；
6. 给出最小修复、临时试用、回滚与复验方案；
7. 未经确认不永久修改用户配置。

## 4. 分层分析与智能授权

分析顺序固定为：

1. **确定性脚本和规则**：能复跑、能解释、成本低的判断必须先固化；
2. **本地统计和启发式评分**：用于发现模式和生成风险分，不把相关性伪装成因果；
3. **授权后的模型分析**：只处理无法可靠固化的语义与判断密集问题。

小新不得静默发起额外模型分析。每次建议启动智能分析时，必须先向用户展示：

- 为什么需要模型参与；
- 已有的确定性证据和仍然未知的部分；
- 将发送的数据范围，是否包含原任务内容；
- 模型、推理深度、只读/写入权限和预计成本范围；
- 分析完成后会产生什么结果以及是否需要第二次执行授权。

用户明确确认后才能创建分析会话。分析会话默认：

- 最小证据包，不继承完整原会话；
- 使用 `fork_turns: none` 或等价隔离；
- 只读、单次、有 Token 与时间上限；
- 不自动派生更多 Agent；
- 同一问题去重并设置冷却时间；
- 分析授权与执行修复授权分离。

## 5. 证据纪律

所有产品结论必须标记为以下一种：

- **已观测事实**：来自本地结构化事件或 provider 事实；
- **规则命中**：满足可复跑的确定性条件；
- **合理推断**：存在相关证据，但因果或语义仍未验证；
- **模型分析**：经过用户授权，由隔离会话给出的判断；
- **已验证结论**：经过可比实验、测试或修复后复验；
- **未知**：证据不足，保持未知。

静态代码存在、单元测试、真实运行链路和用户体验验收是不同证据等级，不得互相替代。

## 6. 主产品与非目标

主产品只展示能够解释状态、影响用户决策或提供行动的结论。菜单栏和小新悬浮层是低打扰入口，不是研究数据仪表盘。

小新不做：

- 预测用户下一项任务；
- 要求用户持续学习或手动选择模型配置；
- 根据历史使用次数直接宣布最佳模型；
- 展示没有决策作用的累计样本和静态审计历史；
- 为节省 Token 牺牲验证质量和必要安全门禁；
- 在低置信度下擅自中断任务或修改配置；
- 未经用户确认静默创建诊断模型会话。

会话列表、快速打开、配额、宠物动画和主题属于支撑体验，不得挤压三个核心闭环的实现与验证。

## 7. 核心指标

- 已验证任务成功率与一次完成率；
- 每个已验证有效结果的 provider Token 和返工成本；
- 路由升降档后的质量、Token、耗时与撤回率；
- 可避免消耗的发现与实际阻止量；
- 执行偏航和工作流回归的发现时间；
- 提醒的误报率、漏报率、采纳率和处理结果；
- 用户手动选择模型与推理深度的次数；
- 配置修复后的复验成功率。

不能证明提升上述指标之一的功能，不进入核心路线。

## 8. 变更控制

以下内容视为冻结：核心定位、三个核心闭环、`sol / medium` 默认入口、脚本优先、模型分析需显式授权、证据等级和质量优先目标。

后续若要改变，必须同时提供：

1. 新的用户问题与证据；
2. 对核心指标的预期影响；
3. 与当前定位冲突的具体位置；
4. 可逆实验和退出条件；
5. 用户明确确认。

关键技术前提与验证状态见[《核心技术探针与证据账本》](TECHNICAL_SPIKES.md)。阶段路线和历史实验继续记录在[《小新 Token 效率战略与分阶段执行计划》](TOKEN_EFFICIENCY_STRATEGY.md)，但不得覆盖本宪章。
